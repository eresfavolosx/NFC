## 2026-04-08 - Avoid N+1 Map Pre-fetching Micro-optimizations
**Learning:** Pre-fetching Maps and replacing simple property getter calls inside loops with closures or pre-fetched map references is considered a 'useless micro-optimization' and an architectural anti-pattern in JS, as property access is extremely fast. Additionally, attempts to provide default fallbacks using arrays (e.g., `[]`) inside those loops degrades memory by allocating unused arrays.
**Action:** Do not attempt to optimize O(N) property getters that rely on internal lazy-caching Maps. If a fallback array is absolutely necessary, subclass the `Map` to return a shared `Object.freeze([])` instance to avoid memory bloat.
## 2026-04-09 - Avoid premature reduce micro-optimizations for arrays
**Learning:** Replacing `.filter(...).length` with `.reduce(...)` for counting elements is considered a premature micro-optimization in this codebase. The application's data size does not realistically reach the hundreds of thousands of items required for avoiding intermediate array allocations to yield any measurable real-world performance gain, and such optimizations should be avoided unless a real bottleneck is present.
**Action:** Do not attempt to optimize array iterations that do not show an actual bottleneck. Instead, if no clear optimization is found that yields measurable impact on cold paths, do not create a PR.
